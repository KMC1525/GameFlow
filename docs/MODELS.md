# Local models guide

*[Português (Brasil)](MODELOS.md)*

GameFlow works with no AI at all (built-in generators). For freer text, stories, mechanics and art, plug in local models under **⚙ Settings → Agents**. Each task (text, code, image, sound) can use a different model.

Run `gameflow doctor` at any time to see which programs GameFlow found.

## Text and code

### Option A — llama.cpp with GGUF models from Hugging Face (recommended)

1. Install `llama-server`:
   - macOS / Linux (Homebrew): `brew install llama.cpp`
   - Windows and others: download the binaries from <https://github.com/ggml-org/llama.cpp/releases> and put the folder on your `PATH` — or set the path in **Settings → Avançado**.
2. In **Settings → Models (Hugging Face)** download a GGUF model. Suggestions (the "Recommended" list already includes them):
   | Use | Model | Approx. size |
   |---|---|---|
   | getting started / modest PCs | `Qwen/Qwen2.5-Coder-1.5B-Instruct-GGUF` (`q4_k_m` file) | ~1 GB |
   | balanced | `Qwen/Qwen2.5-Coder-3B-Instruct-GGUF` | ~2 GB |
   | best code | `Qwen/Qwen2.5-Coder-7B-Instruct-GGUF` | ~5 GB (16 GB RAM) |
   | story/dialogue | `bartowski/Llama-3.2-3B-Instruct-GGUF`, `Qwen/Qwen2.5-7B-Instruct-GGUF` | 2–5 GB |
3. Click **Use for code** (or text) next to the downloaded model, then **Agents → Test**.
4. With a GPU, add `-ngl 99` under "Extra arguments".

GameFlow starts `llama-server` by itself the first time an agent needs it and stops it when you quit.

### Option B — Ollama, LM Studio or any OpenAI-compatible server

Choose **OpenAI-compatible local server** and enter:

| Program | Address | Example model |
|---|---|---|
| Ollama | `http://127.0.0.1:11434/v1` | `ollama pull qwen2.5-coder:7b` → name `qwen2.5-coder:7b` |
| LM Studio | `http://127.0.0.1:1234/v1` | the name shown in the "Local Server" tab |

## Images

### stable-diffusion.cpp

1. Install [stable-diffusion.cpp](https://github.com/leejet/stable-diffusion.cpp) (the executable is `sd-cli` in recent versions, `sd` in older ones — GameFlow looks for both).
2. Download an image model (e.g. `second-state/stable-diffusion-v1-5-GGUF`) in the Models tab.
3. Pick **stable-diffusion.cpp** for the image agent and select the file. "Extra arguments" accepts flags such as `--steps 20`.

If you attached reference images, the first one is passed as the init image (`-i`) to guide the style. The style's negative prompt is passed with `-n`. Sprites generated by a model get their plain background removed automatically. Choose a [style preset](STYLE_PRESETS.md) to steer every image the same way.

### Other generators

- **Compatible server** (`/v1/images/generations`): enter address and model.
- **Custom command**: use `{prompt}`, `{negative}`, `{out}`, `{model}`, `{w}`, `{h}`. Example: `python generate.py "{prompt}" {out} --size {w}x{h}`.

## Sound

- Default: the built-in synthesizer (effects and chiptune soundtrack matching the theme).
- **Custom command**, for example [Piper](https://github.com/rhasspy/piper) for voices (`.onnx` models in `rhasspy/piper-voices`):

  ```
  piper --model {model} --output_file {out}
  ```

  When the command does **not** contain `{prompt}`, the text is sent on standard input (as Piper expects). Available placeholders: `{prompt}`, `{out}`, `{model}`, `{kind}` (`sfx`/`music`), `{duration}`.

## Tips

- A model failure never breaks generation: the agent warns and uses the built-in generator.
- Large models on CPU can be slow — raise the timeout under **Avançado**.
- "Gated" models (that require accepting a license) need a Hugging Face token (Settings → Models).
- Files live under `gameflow paths` → "dados e modelos"; delete them from the interface or straight from the folder.
